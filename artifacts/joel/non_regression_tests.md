# Specialization A – Collection of Non-Regression Tests

This document describes the non-regression tests for issues identified through Atheris fuzzing of the Tatou API. The executable tests are maintained in server/test/; this document maps each test function to the behavior it verifies.

For the identified bugs and fixes, see [bugs_discovered.md](bugs_discovered.md). 

For the Atheris campaigns and their results, see [fuzzing_results.md](fuzzing_results.md).

## A-01 – PDF Upload

Endpoint: POST /api/upload-document  
Test file: [test_regression_a01.py](../../server/test/test_regression_a01.py)

| Test function | Verified behavior | Expected status |
|---|---|---|
| `test_rejects_plain_text` | Rejects plain-text content uploaded with a PDF filename. | 4xx |
| `test_rejects_empty_file` | Rejects an empty uploaded file. | 4xx |
| `test_rejects_malformed_pdf` | Rejects malformed content beginning with a PDF header. | 4xx |
| `test_accepts_valid_pdf` | Accepts a valid, generated PDF. | 201 |
| `test_requires_authentication` | Rejects a PDF upload without an authentication token. | 401 |
| `test_rejects_invalid_token` | Rejects a PDF upload with an invalid bearer token. | 401 |

The three invalid-content tests assert that the response is within the HTTP 4xx range; they do not require specifically HTTP 400. The fixture creates a test account and removes its documents, files, and user record during cleanup.

Documented results: Before the PDF validation fix, 3 of 6 tests passed and 3 failed (plain text, empty file, and malformed PDF). After the fix, 6 of 6 passed. 

## A-02 – Create Watermark

Endpoints: POST /api/create-watermark/<document_id> and POST /api/create-watermark 
Test file: [test_regression_a02.py](../../server/test/test_regression_a02.py)

| Test function | Scenario / verified behavior | Expected status | Test cases |
|---|---|---|---:|
| `test_owner_can_create_watermark` | Owner creates a watermarked version; response contains the document ID and the database contains one version. | 201 | 1 |
| `test_nonowner_cannot_create_watermark_with_path_id` | Another authenticated user cannot create a version using the document ID in the URL; no version is created. | 404 | 1 |
| `test_nonowner_cannot_create_watermark_with_json_id` | Another authenticated user cannot create a version using the document ID in the JSON body; no version is created. | 404 | 1 |
| `test_unauthenticated_user_cannot_create_watermark` | An unauthenticated request is denied; no version is created. | 401 or 403 | 1 |
| `test_rejects_invalid_intended_for_type` | Rejects intended_for supplied as a JSON list; no version is created. | 400 | 1 |
| `test_rejects_empty_watermark_credentials` (secret) | Rejects an empty `secret`; no version is created. | 400 | 1 |
| `test_rejects_empty_watermark_credentials` (key) | Rejects an empty `key`; no version is created. | 400 | 1 |

The final two cases are generated by @pytest.mark.parametrize("field", ["secret", "key"]). The fixture sets up an owner, a second user, and a PDF document, then cleans up created database records and test files.

Documented final result: 7 of 7 passed after the fixes. 

## A-03 – Login

Endpoint: POST /api/login  
Test file: [test_regression_a03.py](../../server/test/test_regression_a03.py)

| Test function | Scenario / verified behavior | Expected status | Test cases |
|---|---|---|---:|
| `test_valid_login_returns_token_and_ttl` | Correct credentials return a nonempty string token, bearer token type, and an integer expires_in (not a Boolean). | 200 | 1 |
| `test_missing_credentials_are_rejected` | Missing email or missing password is rejected. | 400 | 2 |
| `test_invalid_credentials_are_rejected` | Wrong password or unknown email is rejected. | 401 | 2 |
| `test_invalid_credential_types_are_rejected` | Rejects email and password when each is supplied as a list, object, or Boolean. | 400 | 6 |
| `test_non_object_json_is_rejected` | Rejects a top-level JSON array, string, number, or Boolean. | 400 | 4 |

The last four groups use parametrized cases where specified. The test fixture creates a unique account and deletes it during cleanup.

Documented final result: 15 of 15 passed.

## Overall Results

| Campaign | Final passed | Total |

| A-01 – PDF Upload | 6 | 6 |
